# 小智本地记忆库任务计划

日期：2026-11-13。基线：`e87e229aa014a426469d57df2fe2d1342e6fc2f1`。工作分支：`feature/local-memory-20261113`。

## 已确认的目标

继续使用官方小智已接入的聊天模型，由该模型通过 MCP 读取材料、提炼和整理记忆。家庭设备保存完整文字对话、原始工具消息、来源、记忆版本与概要。本功能不新增模型或向量服务的付费 API，也不把官方 MCP 接入点当作通用模型 API。

费用约束是「不额外购买模型调用」，允许小智聊天模型参与提炼。客户端不能承诺官方服务永久免费、无限额度，亦不能承诺尚未验证的无人值守批量模型调用。

## 实现选择与依据

1. 在现有仓库增加独立的 `src/memory` 模块，使用现有 MCP SDK、Node 内置 SQLite 和 stdio 接入已有工具聚合器。没有必要整套引入图数据库或另一个模型网关。
2. 原文、结构化记忆、概要分层保存。记忆必须引用真实消息 ID、消息版本和精确引文；概要引用记忆版本。来源修改后，依赖内容失效，等待重新提炼。
3. 模型负责理解语义；代码负责来源、角色、作用域、版本、时间、幂等和事务校验。引文匹配不是语义正确的证明，不能将代码测试成绩当作模型提炼准确率。
4. 默认不推断家庭成员身份。未知说话人限制在对应会话；只有操作者显式配置单人身份后才可跨会话归到同一人。模型不能选择其他智能体或数据库。
5. 第一版只支持一个智能体的独立部署。现有工具聚合层不携带可信的调用端点或说话人标识；多智能体使用分开的实例和数据目录，不能共享同一记忆工具来冒充隔离。
6. 精确重复合并来源；相似内容仅作为比较候选。明确纠正才能替换同一主体、属性和条件下的旧状态，保留旧版本。晚到的旧历史不能回滚较新状态。无法确定的冲突进入候选区。
7. 历史同步仅访问已核实的官方路径，完整分页和幂等写入。账号凭据通过本机文件提供，不放入模型参数、日志或仓库。认证失败停止并保留已存档内容，不猜测刷新接口。

## 提炼流程

1. 同步程序保存完整原始消息，生成本地稳定 ID 和不可变修订。
2. 小智模型调用读取材料工具，取得原文、真实来源 ID、版本和相关旧记忆；不把材料里的指令当作系统指令。
3. 模型提交少量结构化事实：主体、属性、内容、条件、断言类型、有效时间、来源引文及新增／补证／纠正意图。
4. 本地执行校验。推断和不确定冲突只保存为候选；正式条目表示「某人明确这样说过」，不表示外部事实已经核实。
5. 检索默认只返回有效正式记忆，并携带来源和时间；历史、候选单独查询。原始对话不会被摘要覆盖。
6. 概要由小智模型提交并引用现有记忆版本。源记忆改变，概要自动失效；需要时重新生成。
7. 本机管理命令支持查看状态、导入、同步、导出／备份和撤销；不开放任意文件路径、凭据或数据库操作给模型。

## 开工前复核结论

设计可执行，已纳入以下必要修正再开工：

- stdio 服务固定配置文件路径，每次调用检查单端点并校验端点绑定；配置修改不能让另一个智能体访问旧库。
- 记忆工具参数和结果含原话，必须对现有调试日志及工具调用日志隐藏正文。
- 写入使用稳定幂等键和事务，防止 MCP 自动重试创建重复记忆或重复纠正。
- 同步完成状态只在整轮成功并复查分页后记录。失败数据保留，重复页依靠消息 ID 去重；无法收敛时显示未完成。
- 采用 Node 22.12 已具备的 SQLite API，备份不能只复制 WAL 模式下的主数据库文件。
- 原始材料只能来自同步器或本机导入，模型提交的暂存内容不能反过来充当自己提炼结果的证据。

## 必须覆盖的错误场景

- 将妻子的偏好归给说话人；将助手建议当作用户确认。
- 抹掉否定、数量、条件、时间；把今天的操作当作永久偏好。
- 白天与夜间的温度互相覆盖；计划购买被记成已经拥有。
- 用同一句原话编造不同意义；用不存在的消息或过期修订作证。
- 新信息先导入、旧历史后导入，当前状态回滚。
- 重复导入虚增证据；补录到一半失败；服务重启后进度无法恢复。
- 纠正来源后旧概要仍被当作有效；撤销覆盖后续更新。
- 多端点共用工具导致家庭成员或智能体之间串库。
