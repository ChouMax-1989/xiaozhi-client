# 小智角色介绍：本地记忆追加规则

先按[部署说明](nas-memory-deployment.md)接通记忆服务。在「看板 → 小智角色提示词」复制下方规则，到小智 AI 官方控制台打开对应智能体的「角色介绍」，开启「自定义」，把规则追加到现有人设末尾并保存。「记忆库 → 设置」也提供同一份规则。升级时只替换上次追加的规则段。

工具名以小智实际发现的列表为准；服务名为 memory 时通常是 memory__memory_search 等。工具启停或升级后，让小智重新发现工具或重连。复制规则不需要网页登录凭据，也不改变同步设置。角色保存不等于设备已生效，按官网提示重启设备后再验证。

```text
正常聊天时先回应，保持原有人设。开聊、普通聊天和自然告别都不触发对话归档、记忆提炼或历史批量整理；用户告别时自然道别。
用户问起往事，优先用 memory__memory_search 查本地相关记忆，可传 includeCandidates:true 查候选线索；候选和暂存内容未验证，不能当作已确认事实。没有查到时如实说明，不编造。
用户明确托你记住某件事时，按当前实际可用的本地工具暂存该事项，可用 memory__memory_capture_candidate；保留用户原话、主体和条件，按工具结果说明是否暂存成功，不把暂存称为正式记忆或已完成提炼。不要扩展为归档整段对话。
用户请你操作设备时，调用对应工具，按结果回答。只有用户明确要求整理记忆或历史时才处理该项任务；工具可用不代表后台模型或无人值守提炼已经可用，不承诺未经验证的后台能力。
```

看板会按本地服务名生成工具全名。明确批量整理时用 memory__memory_read_sources 的 bulk:true，每次读取一条；长原文按返回的 nextOffset 用 memory__memory_read_source 的 compact:true 继续读取，读完整条并处理后才标记已审阅。

## 启用后检查

1. 请小智调用 memory_status，确认接入的是预期智能体。
2. 普通开聊和自然告别应直接回应，不等待归档或提炼。明确托记一项偏好时，检查本地工具回执和未验证暂存，不把它当作正式记忆。
3. 要求读取一条长文本，确认 memory_read_result 连续读取到 nextOffset:null；原文自己的分页也应读完。1024字节是完整工具响应的上限，不是每段固定有1024字节正文。
4. 开新对话检索刚保存的内容。模型来源提炼仍是候选，不能把候选称为已确认事实。图谱只展示本地存量记忆关联，不改变提炼及检索能力。

打算关闭官方记忆时，先核对历史对话归档是否齐全，用 memory_status 检查待整理消息数量；检查提炼出的记忆和原话是否对应，备份数据库。随后在真实智能体上用一条仅存于本地库的测试记忆做跨会话检索，核对看板工具调用记录。通过后再关闭官方记忆，用新对话复测一次。官方已经生成的用户画像和记忆条目需要单独核对是否已在本地覆盖。

已验证本机存储、工具传输与分段还原。真实模型遵循新角色规则、设备重启后的效果，以及后台模型或无人值守提炼能力，需要分别验证，不能由角色保存或网页开关推断。
