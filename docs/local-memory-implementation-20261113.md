## 复核后修正的问题

1. 现有多个端点共享工具聚合器。记忆服务固定单智能体和配置路径，每次调用重新检查单端点及指纹，防止配置更换后访问旧库。
2. 未来或缺失时间的来源只能作为候选，不能通过「补证」抬高正式事实的观察时间。
3. 纠正时间只取包含纠正引文的消息，不能附加一条无关新消息给旧纠正刷新时间。
4. 来源变更使记忆及概要失效；旧请求重试返回当前状态，不复活旧内容；撤销不覆盖后续修改。
5. 使用专用安全业务错误，底层解析或文件系统异常不会回显原话、路径和凭据。
6. 数据库误指向目录时先拒绝，不改变目录权限。备份采用 `VACUUM INTO`，不能只复制 WAL 模式下的主数据库文件。
7. 备份测试仅在支持 POSIX 权限的系统断言 `0600`，备份生成、重新打开与内容完整性仍在所有平台检查，避免把 Linux 权限位直接套用到 Windows。

代码校验不等于语义正确性证明。正式记忆表示用户曾明确这样说过；反话、隐含条件和转述仍需模型判断。真实语义验收用例见[使用说明](content/usage/local-memory.mdx)。

## 官方接口边界

| 路径 | 已核实并使用的参数 |
| --- | --- |
| `/api/chats/list` | `agentId`、`page`、`pageSize=20` |
| `/api/chats/messages` | `chatId`、`page`、`pageSize=50`、`includeTools=1`、`order=asc` |

按 `data.list`、`data.pagination.page/totalPages` 解析。原文成功保存后才推进页检查点。两个相邻完整扫描的指纹相同才报告完成；持续变化时保留未完成状态。列表少了某聊天不会删除本地旧档案。未知时区不猜测，保存原始值并把标准时间留空。
