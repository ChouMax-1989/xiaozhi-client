# 本地对话档案与记忆库

这个模块把官方小智的文字对话、工具消息和记忆保存在家庭设备的 SQLite 数据库中。小智当前聊天模型通过 MCP 读取原文、提炼信息和整理概要；本地程序校验来源、作用域、时间与版本，不调用新的模型或向量 API。

这是可选功能。普通客户端和现有家庭工具仍按原配置运行。第一版适用于一个智能体的独立实例；多个智能体请使用分开的容器、配置和数据库。

任务与复核依据见[任务计划](../../plans/local-memory-20261113.md)。实际完成的验证与尚待联调的项目见[实施记录](../../local-memory-implementation-20261113.md)。

## 可以做什么

| 能力 | 实际行为 |
| --- | --- |
| 官方历史同步 | 读取已核实的聊天列表和消息接口，保留用户、助手及工具的原始 JSON；分页、断点和幂等写入 |
| 本地原文 | 原话修改时追加修订，旧原话保留；音频只保留官方返回的地址及元数据，不下载录音 |
| 提炼记忆 | 现有小智聊天模型提交结构化事实，每条附真实消息 ID、修订和精确引文 |
| 条件与归属 | 区分说话人、关联人物和实体；不同条件分别保存；未知身份按会话限定 |
| 纠正和版本 | 只有明确纠正才替换对应状态；晚到历史不回滚新状态；原版本和操作记录保留 |
| 检索 | 本地关键词、主体属性和条件匹配；默认只返回有效正式记忆，没有另购 embedding 服务 |
| 概要 | 引用现有记忆版本；来源改变、被纠正、失效或撤销后，旧概要不再作为有效结果返回 |
| 网页管理 | 在 `/memory` 查看记忆、对话、来源修订、摘要及操作记录；停用和撤销记忆，配置同步，导出与备份 |
| 运维 | 保留本机命令用于导入档案、恢复和端点重新绑定；不向模型暴露文件操作或凭据 |

正式条目表示「用户曾明确这样说过」，不是外部事实验证结果。引文匹配、角色和版本校验能拒绝伪造来源，但不能证明模型完全理解了反话、转述或条件句。推断、计划、单次事件和含糊冲突先保留为候选。

## 运行条件

- 使用本仓库包含记忆模块的源码构建版本。旧 npm 包或上游镜像不包含这些改动。
- Node.js 至少 22.12。示例始终带 `--experimental-sqlite`，兼容需要显式启用 SQLite 的版本。
- 客户端只配置一个非空 WSS 接入点。记忆服务启动及每次调用都会重新核对配置；添加第二个端点或更换端点会拒绝访问原库。
- 官方历史同步需要本机的官方控制台 HTTP 登录凭据。它与 MCP 接入地址里的令牌是不同用途，不能互换。

没有 HTTP 凭据也可以运行离线导入、存储、检索和 MCP。定时同步默认关闭。原始历史可以定时同步，但语义提炼仍发生在小智聊天模型实际调用工具时；目前不提供无人值守的免费模型批处理承诺。

## 网页管理与设置

启动当前源码构建版本后，从 WebUI 顶部进入「记忆库」，也可以打开同一地址下的 `/memory`。页面使用本机真实数据库，不依赖浏览器保存对话或记忆。

### 第一次配置

1. 先在客户端配置中保留一个有效的小智 MCP 接入点，再进入记忆库的「设置」。
2. 填写这个智能体的 ID。只有明确单人使用时才填写身份标识；多人共用或身份未确定时留空。
3. 保存后按页面提示重启客户端，使新记忆服务或同步参数生效。Docker 部署在 NAS 管理界面重启容器，或在源码目录执行 `docker compose -f docker/docker-compose.yml restart xiaozhi-client`；页面会显示对应指引。页面显示「需要重启」时，不能当作已经应用新配置。
4. 如果需要同步官方历史，在「历史凭据」中输入官方控制台 HTTP Bearer 凭据的值并保存。这里不填写 MCP 接入地址，也不填写额外模型 API Key。
5. 自动同步默认关闭。先执行一次手动同步并查看结果，再按需要启用定时同步。开启后间隔至少 60 秒，每轮请求预算为 1 到 1000。

凭据使用密码输入框，只能写入；保存后输入框清空，接口不返回令牌，也不把它存进浏览器本地存储。服务将其写入配置目录下固定的 `secrets/xiaozhi-history-token` 文件。Linux 文件权限为 `0600`，目录为 `0700`。已有自定义凭据文件的部署仍按其配置读取；网页保存新凭据后改用受管理的固定文件。

数据库路径由本机配置决定，网页只读显示。数据库建立后智能体和身份模式锁定，避免把另一人的数据接到已有记忆库。已有多个记忆服务或多个接入点时，页面会提示先整理本机配置。

### 管理页面中的操作

| 页面 | 操作与含义 |
| --- | --- |
| 记忆 | 按关键词和状态筛选，分页查看正式、候选和失效条目；详情展示条件、归属、理由、历史版本以及精确原话 |
| 对话 | 搜索会话和原文，查看用户、助手及工具消息；不允许在网页里改写原话给记忆重新作证 |
| 摘要 | 查看最近 100 条摘要及其记忆引用；来源变化后失效的摘要仍可追溯，但不会重新提供给模型作为有效结论 |
| 操作记录 | 查看最近操作并撤销仍可恢复的变更；如果已有后续修改或旧来源失效，禁止覆盖恢复 |
| 设置 | 配置智能体、单人身份、历史凭据、同步间隔和请求预算；导出完整 JSON 或下载 SQLite 备份 |

「停用」会要求理由，保留原记录并增加版本；它不是永久删除。仅当前正式或候选条目可以停用。相应摘要会失效；在操作记录中撤销停用后，摘要也不会自行复活，需重新基于当前记忆整理。来自当前聊天的暂存内容另列为「未核验」，不能直接在页面中批准为真实来源。

来源详情同时标明「引用时的修订」和「当前修订」。原话变过时展示的是当时真正引用的版本，不会偷偷换成最新正文。网页管理与模型工具共用同一套版本、来源和端点校验。

### 同步、提炼和备份

手动同步在后台执行，页面会显示进行中、完成、未完成或失败。预算用尽不等于同步完成；失败不会清除已有本地档案。开启自动同步或存在待重启配置时，先按页面提示处理，再发起手动同步，避免两套同步任务重叠。

「复制整理提示」把提示语复制出来，供你发送到小智聊天。实际提炼仍由当前小智模型调用 MCP 完成；网页不额外调用付费模型，也不把复制提示伪装成已经提炼完成。

JSON 导出包含完整档案和审计资料；SQLite 下载是通过数据库一致性备份生成的文件。网页不接受任意服务器路径，也没有覆盖数据库的恢复按钮。恢复仍按下面的本机步骤，先停止服务并保留原库。

管理接口与现有 WebUI 使用相同访问边界，拒绝其他网页来源直接读取或修改记忆，并禁止响应缓存。它没有新增家庭成员登录系统；只向受信任的本机或家庭网络开放。

## Docker 接入

完整示例位于 `docker/examples/memory.config.json`。在当前配置里增加 `mcpServers.memory`，保留已经设置的其他工具，并填入当前智能体的 ID。不要用示例覆盖已有配置。

```json
{
  "mcpEndpoint": "wss://请替换为该智能体的官方完整MCP接入点",
  "mcpServers": {
    "memory": {
      "command": "node",
      "args": ["--experimental-sqlite", "/app/dist/memory/stdio.js"],
      "env": {
        "XIAOZHI_MEMORY_AGENT_ID": "请替换为智能体ID",
        "XIAOZHI_MEMORY_DB": "/workspaces/memory/archive.sqlite",
        "XIAOZHI_MEMORY_CLIENT_CONFIG": "/workspaces/xiaozhi.config.json",
        "XIAOZHI_MEMORY_TOKEN_FILE": "/workspaces/secrets/xiaozhi-history-token",
        "XIAOZHI_MEMORY_SYNC_INTERVAL_SECONDS": "0"
      }
    }
  },
  "webUI": { "port": 9999 }
}
```

`XIAOZHI_MEMORY_CLIENT_CONFIG` 必须显式填写绝对路径，因为 stdio 子进程不会自动继承父进程的全部自定义环境变量。数据库和凭据文件都位于现有 `/workspaces` 持久化挂载中。

先完成源码构建与客户端配置，再重启：

```bash
docker compose -f docker/docker-compose.yml up -d --build
docker compose -f docker/docker-compose.yml logs --tail=100
```

在 WebUI 工具列表里应看到 `memory__memory_status` 等工具。调用状态工具应返回档案与记忆数量。正文在日志中会被隐藏；工具调用者仍会收到真实查询结果。

### 配置项

| 环境变量 | 要求或默认值 | 作用 |
| --- | --- | --- |
| `XIAOZHI_MEMORY_AGENT_ID` | 必填 | 固定智能体；模型参数不能修改 |
| `XIAOZHI_MEMORY_DB` | 必填，绝对路径 | SQLite 文件，首次创建绑定智能体和身份模式 |
| `XIAOZHI_MEMORY_CLIENT_CONFIG` | MCP 必填，绝对路径 | 每次工具调用核对单端点及绑定 |
| `XIAOZHI_MEMORY_TOKEN_FILE` | 可选，绝对路径 | 同步器读取的 HTTP Bearer 凭据文件；不返回给模型 |
| `XIAOZHI_MEMORY_OWNER` | 默认不设置 | 仅当该智能体明确只由一个人使用时填写稳定本地标识，例如 `max`；允许跨会话合并为该人 |
| `XIAOZHI_MEMORY_SYNC_INTERVAL_SECONDS` | `0` | `0` 关闭；启用时至少 60 秒，最多 2147483 秒 |
| `XIAOZHI_MEMORY_SYNC_MAX_REQUESTS` | `20` | 自动同步每轮请求预算，1 到 1000；预算用尽后保存进度 |

未配置 `OWNER` 时，记忆仍然可以保存，归属形式是 `chat:会话ID:unknown`。这是未知说话人的会话范围，并不代表已确认某个人。不要在多人共用的智能体上设置一个固定户主身份。数据库已绑定的身份模式不能直接改名复用；身份迁移需核对后另做迁移。

当前 `/mcp`、WebUI 和家庭工具使用同一应用访问边界。端点检查防止配置串库，不是完整的家庭成员鉴权；有权访问本机管理界面的人也能调用工具。保留在受信任的本机或家庭网络，不要公开服务端口。

### 官方历史凭据

在自己的部署机器上，通过已登录的官方控制台取得历史接口使用的 Bearer 凭据，保存在 `secrets/xiaozhi-history-token` 文件中；文件只包含凭据值，不含 `Bearer ` 前缀，不要贴到聊天、代码或截图中。目录权限建议 700，文件权限 600。

可以通过本机文件或上面的网页密码输入框保存凭据；不会自动读取浏览器登录信息，也不假设官方刷新接口或固定有效期。遇到 401/403，同步停止本轮且保留本地数据；更新凭据后重试。官方开发者接口是否对个人账号开放尚未确认，本模块不依赖该接口。

确认单次同步成功后，可把同步间隔改为例如 `300`。两个连续完整扫描的列表和消息指纹一致才报告 `complete`；预算用尽、超时、限流、分页变化都保持未完成。远端分页没有快照保证，持续发生变化时需要后续继续核对；本地不会因一轮列表缺少某聊天而删除旧档案。

## 本机管理命令

源码构建后使用 `node --experimental-sqlite dist/memory/cli.js`。先配置本机路径和智能体：

```bash
export XIAOZHI_MEMORY_AGENT_ID=你的智能体ID
export XIAOZHI_MEMORY_DB=/绝对路径/memory/archive.sqlite
export XIAOZHI_MEMORY_TOKEN_FILE=/绝对路径/secrets/xiaozhi-history-token
node --experimental-sqlite dist/memory/cli.js status
node --experimental-sqlite dist/memory/cli.js sync --max-requests 100
```

Docker 内的 CLI 也需要显式环境变量；`mcpServers.memory.env` 只传给对应子进程，不会自动变成容器全局变量：

```bash
docker compose -f docker/docker-compose.yml exec \
  -e XIAOZHI_MEMORY_AGENT_ID=你的智能体ID \
  -e XIAOZHI_MEMORY_DB=/workspaces/memory/archive.sqlite \
  -e XIAOZHI_MEMORY_TOKEN_FILE=/workspaces/secrets/xiaozhi-history-token \
  xiaozhi-client node --experimental-sqlite /app/dist/memory/cli.js sync --max-requests 100
```

`status` 显示数量和最近同步核对信息，`sync` 打印本轮安全摘要，不打印原话或令牌。原文保存成功但尚未收敛时可以再次运行 `sync`；不要把 `incomplete` 当成全量完成。

### 离线导入格式

本机 `import` 接受 `messages` 数组及可选的 `chats` 数组，最多各 10000 项。消息 ID 使用原平台稳定 ID，不要为重复导入随机生成 ID。完整原始信封放入 `raw`。

```json
{
  "chats": [{ "id": "chat-1", "raw": { "title": "设置讨论" } }],
  "messages": [{
    "id": "message-1",
    "chatId": "chat-1",
    "role": "user",
    "content": "我希望卧室夜间保持26度。",
    "createdAt": "2026-11-13T10:00:00+07:00",
    "raw": { "id": "message-1", "role": "user", "content": "我希望卧室夜间保持26度。" }
  }]
}
```

```bash
node --experimental-sqlite dist/memory/cli.js import /绝对路径/archive.json
```

没有可靠时区的时间用 `null`，不要自动补成服务器时区。这类来源仍存档，但无法据此自动纠正较新的当前事实。

### 备份、恢复和撤销

```bash
node --experimental-sqlite dist/memory/cli.js backup /绝对路径/backups/memory-20261113.sqlite
node --experimental-sqlite dist/memory/cli.js export /绝对路径/backups/memory-20261113.json
node --experimental-sqlite dist/memory/cli.js operations --limit 20
node --experimental-sqlite dist/memory/cli.js undo 操作ID
```

备份使用 SQLite `VACUUM INTO`，包含已提交的 WAL 数据，不能用只复制主 `.sqlite` 文件的方式替代。恢复时先停止记忆服务，用备份文件作为一个新的数据库路径，保留原文件，确认 `status` 和来源数据后再启用。备份包含绑定和同步检查点；更换智能体或身份配置不能直接复用。

完整 JSON 导出供检查与迁移，含原始修订、记忆版本和审计记录，不是 `import` 的简化输入格式。整库恢复使用 SQLite 备份。撤销会检查后续修改及旧来源有效性，有冲突时拒绝覆盖。

同一智能体轮换 MCP 接入令牌后，先在本机核对新的客户端配置，再执行 `rebind-endpoint`；该命令需要 `XIAOZHI_MEMORY_CLIENT_CONFIG`，会核对已知智能体标识并记录重新绑定操作。不要用它把其他智能体接到原库。

## 让小智开始提炼

在小智角色说明里加入以下约定，并让模型实际调用已列出的工具。聚合后工具名带服务名前缀，以当前工具列表为准：

> 需要个人历史时，先查询本地记忆。整理记忆时，先读取待处理原文和提炼规则；原文截断则继续分段读取。每条记忆保留真实来源 ID、版本和原话，区分否定、条件、人物和时间。只有用户明确纠正才替换旧版本；不确定的内容暂存候选。读完并完成处理后才标记来源已审阅。概要只基于当前有效记忆。

初次可以说：「请整理本地记忆库中尚未处理的对话，每次处理少量，先告诉我还有多少待处理；保存时不要丢掉人物、否定和条件。」

记忆 MCP 提供以下工具：

| 工具原名 | 用途 |
| --- | --- |
| `memory_status` | 数量和同步状态 |
| `memory_read_sources` | 待提炼原文、真实来源 ID、相关旧记忆及规则 |
| `memory_read_source` | 按 ID、版本和偏移量读取长消息或核对引文 |
| `memory_search` | 关键词检索，默认排除候选和历史失效条目 |
| `memory_submit` | 提交新增、补证或明确纠正，代码校验后保存 |
| `memory_finish_sources` | 标记已经审阅的来源版本 |
| `memory_save_summary` | 保存引用记忆版本的概要 |
| `memory_read_summaries` | 读取仍然有效的概要 |
| `memory_capture_candidate` | 当前对话未同步时暂存，不能冒充原文证据 |

待提炼队列可以查询，系统不会定时偷偷调用另一个模型。工具实际是否被官方模型正确选择、一次能处理多少材料，要在真实小智对话中验收。官方原有记忆功能与本地库相互独立，本模块不会修改或同步覆盖官方的 20 条记忆设置。

## 语义验收

存储测试验证来源、时间、事务和版本规则。模型语义验收要另测，不能用存储测试通过率代替。建议把以下原句作为真实小智的验收材料，逐条检查原文、提炼结果与后续检索：

| 原句或顺序 | 应有结果 |
| --- | --- |
| 我老婆不喜欢香菜 | 妻子的用户转述；不是说话人偏好 |
| 我不是不喝咖啡，我只是不喝含糖咖啡 | 保留双重否定和「含糖」条件 |
| 今天卧室调到24度 | 单次事件候选，不生成永久温度偏好 |
| 白天28度，夜间26度 | 两个条件共存 |
| 更正，以后夜间改为25度 | 明确替代夜间旧值，白天值保留 |
| 如果打折，我准备买洗碗机 | 有条件的计划候选，不记作已经拥有 |
| 助手建议睡前读书，用户未确认 | 不保存为用户长期偏好 |
| 先同步新设置，再补录旧聊天 | 较新状态不回滚 |
| 同一份历史重复同步 | 不重复记忆或虚增来源数量 |
| 用户澄清接受小智免费聊天模型提炼，只是不增加付费 API | 保留这个项目范围，纠正「所有 AI 都不可用」的旧理解 |

如果模型遗漏条件、串人物或未核对来源，先调整角色提示和工具使用流程，再重跑上述语义验收；不要为了提高保存数量降低来源校验。
