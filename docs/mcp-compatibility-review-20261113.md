# 小智语音 MCP 接入复核

## 结论

项目使用的接入方式与官方说明相符，本机真实构建的完整调用链通过。2026-11-14 已按用户要求补齐 1024 字节分段返回，长原文重建验证通过（见文末）；尚未连接用户的真实智能体，不能将本机结果标为“官方语音端完整验收通过”。修改保留在工作分支，未提交、未部署 NAS、未改真实档案或官方配置。

## 官方依据

- [小智官方 MCP 接入说明](https://my.feishu.cn/wiki/HiPEwZ37XiitnwktX13cEM5KnSb)：2026-11-13 使用 Chrome 实际读取，页面署名虾哥，标注 2025-09-02 修改。说明本地 MCP 服务通过智能体专属接入点提供给语音终端；强调清晰的工具名/参数/描述和干净的标准输入输出；提到返回通常限 1024 字节、列表 token 与接入点连接数有上限，后两者未给固定数值。
- 该官方页面直接链接的 [78/mcp-calculator 示例](https://github.com/78/mcp-calculator)及 [mcp_pipe.py](https://github.com/78/mcp-calculator/blob/main/mcp_pipe.py)：本地程序主动连接 WebSocket，将 JSON-RPC 与本地 stdio 服务互相转发。公网云端不需要主动访问家庭的管理网页端口。
- [MCP 初始化生命周期](https://modelcontextprotocol.io/specification/2024-11-05/basic/lifecycle)和[工具规范](https://modelcontextprotocol.io/specification/2024-11-05/server/tools)：核对初始化通知、工具发现/调用、错误结果和列表变化能力声明。
- [官方固件设备协议](https://github.com/78/xiaozhi-esp32/blob/master/docs/mcp-protocol.md)属于另一条设备音频连接上的 MCP 封装；不能把设备 `type=mcp/payload` 包装套在上述外部 MCP 接入点 JSON-RPC 上。

## 实际接线

语音终端 → 小智云端模型 → 智能体的 MCP 接入点 → 本项目主动建立的 WSS 连接 → 工具聚合器 → 本地 memory stdio → SQLite。

`9999` 是管理网页默认端口；本地验收的 `19997/19999` 也只是管理端口。实际出站地址使用官方控制台提供的完整 WSS 接入点。记忆工具经名为 `memory` 的服务聚合后，实际暴露为 `memory__memory_record_turn` 等 10 个名称；角色规则应使用工具列表中的实际名称。角色介绍引导模型主动提交，不等于平台提供每轮结束的强制回调或完整云端日志订阅；所查官方说明未提供后一种保证。

Docker 镜像已构建记忆入口，`/workspaces` 是持久卷，Compose 从仓库源码构建。`docker/examples/memory.config.json` 只是示例，仍需在实际配置注册 memory，填写对应智能体 ID 和完整接入点。现有库换接入点会触发绑定保护，须按文档通过本机管理命令重新绑定；不能绕过保护。MCP 逐轮记录不需要官方历史网页登录凭据。

本轮仅检查配置结构，未输出令牌：两个本地实例都配置一个本机占位接入点、注册 memory、设置身份、自动同步为 0。它们尚未连接官方真实智能体。

## 发现并修复

| 问题 | 修复与验证 |
| --- | --- |
| `notifications/initialized` 被当请求回复，发出无 id 的响应 | 分离通知分支；本地 WebSocket 和完整 WSS 联调确认不再多回一帧 |
| 首次连接失败、远端断线后没有自动恢复 | 端点管理器按现有延迟恢复；主动断开/移除/停止取消恢复；手动重连失败状态及重试也已覆盖 |
| 停用标准工具仍出现在云端列表，直接调用仍可执行 | 列表只暴露启用项；标准执行入口独立校验，不能绕过列表；UI 仍可查看全部工具 |
| 工具返回 `isError` 仍计入成功统计 | 按实际结果计数 |
| 声明 `tools.listChanged=true` 却没有可靠通知链 | 改为 false；工具变化后云端需重新读取列表或重连，不虚报推送能力 |
| WebServer 初始化和端点事件日志打印完整接入点 | 改为数量和事件描述；完整联调日志不含完整接入点或合成对话原文 |

自定义 MCP 别名维持既有的独立暴露语义：停用某个标准工具名不等于停用另行配置的自定义别名。当前 memory 示例没有此类别名。MCP 子进程运行中意外退出后的自动恢复未纳入本轮实测，不与 WSS 断线恢复混称。

## 2026-11-14 分段实现与完整调用验证

用户明确要求按1024字节分段并保证原文完整。记忆模块统一将完整 CallToolResult 序列化为 UTF-8 后限制768字节，长结果通过新工具 memory_read_result 续读；接入点将最终记忆工具 JSON-RPC 帧限制1024字节。短结果保持原格式，异常超长错误转为明确失败，JSON编码后超过128字节的请求ID在执行前关闭连接（不截断ID、不执行写入）。工具列表不混用工具调用的字节上限。

分段提供 cursor、连续 offset/nextOffset、totalLength 和 SHA-256。拼接后得到原工具完整JSON；原文的 source revision/nextOffset 分页保持独立，需逐层读完。移除记忆展示结果中原有理由、引文、来源和按体积丢项的缩减。内存快照限8MiB，120秒滑动过期；其他记忆调用或外部SQLite变更使旧快照失效，旧游标明确报错。参数校验错误也统一收敛，避免SDK在处理器前产生超长返回。角色规则已增加续读说明，NAS部署时需使用新版规则。
